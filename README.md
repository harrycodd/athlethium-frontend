# Athlethium

[![CI](https://github.com/harrycodd/fitness-app/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/harrycodd/fitness-app/actions/workflows/ci.yml)
[![codecov](https://codecov.io/gh/harrycodd/fitness-app/branch/main/graph/badge.svg)](https://codecov.io/gh/harrycodd/fitness-app)

An endurance training app for cycling, running, swimming and triathlon.
It builds an adaptive, polarised plan around your availability and fitness, and grows with you
from beginner to pro.

The app is React Native (Expo SDK 57, expo-router). The training engine and API live in
[harrycodd/fitness-app-backend](https://github.com/harrycodd/fitness-app-backend).

## Project history

This repository is an enhancement of [harrycodd/athlethium-react](https://github.com/harrycodd/athlethium-react), the
original Athlethium app (now archived). It has been refined using [Claude Code](https://claude.com/claude-code) to make it ready
for deployment. The backend started as [harrycodd/athlethium-aws](https://github.com/harrycodd/athlethium-aws).

## Architecture

```
src/app/            screens (file-based routing)
  index.tsx         entry gate: login → onboarding wizard → tabs
  (auth)/           login, sign-up, password reset
  wizard.tsx        onboarding: sports, availability, goal, fitness level, Strava
  (tabs)/           home (today), plan (calendar), progress
  settings.tsx      profile, Strava, account deletion
src/lib/
  firebase.ts       Firebase app, Auth (persisted) and Firestore clients
  api.ts            authenticated calls to Cloud Functions (Firebase ID token as Bearer)
  workout-service   live workout subscriptions; asks the backend to plan missing days
  user-service      profile reads/writes
  strava.ts         Strava connect/disconnect via the backend's server-side OAuth
src/hooks/use-auth  auth state + live profile; keeps the profile's time zone current
```

How the app talks to the backend:
- **Reads** go straight to Firestore. Security rules let each user see only their own documents.
- **Training plans** are always generated by the backend's `generate_training_session`
  function. The app calls it for any upcoming day that has no session yet.
- **Live updates:** new sessions, including both halves of a double day, appear through the
  Firestore listener.
- **Strava:** tokens never reach the client. The backend issues the OAuth URL, stores the
  tokens server-side and revokes them on disconnect.

## Running locally

```bash
npm ci
npx expo start            # development build / simulator
```

By default the app uses the production Firebase project. For development, run the backend on the
Firebase Emulator Suite instead (see the backend README) and point the app at it:

```bash
# in fitness-app-backend
npx firebase emulators:start --project demo-athlethium --only auth,firestore,functions,storage

# in fitness-app
EXPO_PUBLIC_USE_EMULATORS=true npx expo start
```

- `EXPO_PUBLIC_EMULATOR_HOST` defaults to `127.0.0.1` (iOS simulator / web).
  - Android emulator: set it to `10.0.2.2`.
  - Physical device: set it to your computer's LAN IP.
- In emulator mode the app uses the `demo-athlethium` project. Auth, Firestore and Functions all
  point at the local emulators, so nothing touches production.
- `EXPO_PUBLIC_FUNCTIONS_BASE_URL` overrides the Functions URL on its own if you ever need it.

## Tests

```bash
npm test               # jest-expo + React Native Testing Library
npm run test:ci        # with coverage (writes coverage/)
npm run typecheck
npx expo lint
```

The smoke tests in `__tests__/` cover the critical flows. They render real screens with Firebase
Auth mocked, an in-memory Firestore (`test/fake-firestore.ts`) and a mocked `fetch` for the Cloud
Functions:

| Test | Flow |
|---|---|
| `screens/login` | sign-in routes to plan or onboarding; bad credentials; empty form |
| `screens/auth-gate` | entry redirects; new accounts get a profile; time zone sync |
| `screens/wizard` | full onboarding (Pro level, Strava connect), validation, save failure |
| `screens/plan` | viewing a day's plan, double days, live updates |
| `screens/home-sync` | opening the app generates missing days and shows them; offline |
| `lib/*` | authenticated API client, emulator config, plan sync, completion toggle, Strava |

## Continuous integration

`.github/workflows/ci.yml` runs on every push and pull request:
1. lint;
2. typecheck;
3. tests with coverage.

The coverage summary is added to the run page. When a `CODECOV_TOKEN` secret is set, coverage is
also uploaded to Codecov (drives the badge above).

Lint backlog: three React Compiler rules are set to warnings in `eslint.config.js`:
- `react-hooks/set-state-in-effect`
- `react-hooks/static-components`
- `react-hooks/immutability`

Existing screens break them. They stay visible as warnings until those screens are refactored;
every other lint error fails CI.

## Releasing

Build with EAS, e.g. `eas build --platform all --profile production`. Release app builds together
with the backend deploy, because the API requires authenticated calls. See the backend's
`docs/DEPLOYMENT_GUIDE.md`.
